Detailed Middleware Documentation

1. Helmet (Chetan)

Definition:
Helmet is a security middleware that sets various HTTP headers to protect the application from well-known web vulnerabilities like XSS attacks, clickjacking, and MIME-type sniffing.

Package: helmet
Installation: npm install helmet

Where Used:

  • Admin Dashboard authentication
  • Delivery Admin Dashboard
  • User Management pages
  • All API endpoints

Code Implementation:

// =============================================================================
// CHETAN - Admin & Delivery Dashboard Security Middleware
// Role: Admin Dashboard, Delivery Admin Dashboard, User Management
// =============================================================================

const helmet = require("helmet");

// Helmet: Sets various HTTP headers for security
// Essential for Admin panels - Protects against: XSS, clickjacking, MIME sniffing
app.use(
  helmet({
    contentSecurityPolicy: false, // Disabled for development (enable in production)
    crossOriginEmbedderPolicy: false, // Allow 3D models loading
  }),
);

console.log("✅ Helmet security middleware enabled (Chetan - Admin Security)");

Security Headers Set by Helmet:

  • X-Content-Type-Options: nosniff - Prevents MIME type sniffing
  • X-Frame-Options: SAMEORIGIN - Prevents clickjacking
  • X-XSS-Protection: 1; mode=block - Enables XSS filter
  • Strict-Transport-Security - Enforces HTTPS

2. Rate Limiting (Chetan)

Definition:
Rate limiting middleware controls the number of requests a client can make to the server within a specified time window. This prevents brute-force attacks and DDoS attempts.

Package: express-rate-limit
Installation: npm install express-rate-limit

Where Used:

  • Login endpoint (/api/auth/login) - 5 attempts per 15 minutes
  • All API endpoints - 100 requests per 15 minutes
  • Admin authentication routes

Code Implementation:

// =============================================================================
// CHETAN - Admin Rate Limiting & Brute-Force Protection
// Role: Admin Dashboard, Delivery Admin Dashboard, User Management
// =============================================================================

const rateLimit = require("express-rate-limit");

// General API Rate Limiter - Protects all admin API endpoints
const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100, // Limit each IP to 100 requests per windowMs
  message: {
    success: false,
    message: "Too many requests, please try again after 15 minutes",
  },
  standardHeaders: true,
  legacyHeaders: false,
});

// Strict Admin Login Rate Limiter (Brute-force protection)
// Prevents unauthorized access to Admin and Delivery dashboards
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 5, // Limit each IP to 5 login attempts per windowMs
  message: {
    success: false,
    message: "Too many login attempts, please try again after 15 minutes",
  },
  standardHeaders: true,
  legacyHeaders: false,
  skipSuccessfulRequests: true, // Don't count successful logins
});

// Store rate limiters for admin route protection
app.set("apiLimiter", apiLimiter);
app.set("loginLimiter", loginLimiter);

console.log(
  "✅ Rate limiting middleware configured (Chetan - Admin Protection)",
);

Usage in Routes:

// Apply login limiter to authentication route
app.post("/api/auth/login", loginLimiter, async (req, res) => {
  // Login logic here
});

3. Morgan (Harsha)

Definition:
Morgan is an HTTP request logger middleware. It logs all incoming HTTP requests to the console and/or a file, which is essential for monitoring server activity and debugging.

Package: morgan
Installation: npm install morgan

Where Used:

  • All HTTP requests to track production activities
  • Manager Dashboard for monitoring order processing
  • Production milestone tracking
  • Delivery assignment logging

Log File Location: /logs/access.log

Code Implementation:

// =============================================================================
// HARSHA - Manager Dashboard Middleware
// Role: Manager Dashboard, Production Milestones, Assign Delivery
// =============================================================================

const morgan = require("morgan");
const fs = require("fs");
const path = require("path");

// Create logs directory if it doesn't exist
const logsDir = path.join(__dirname, "logs");
if (!fs.existsSync(logsDir)) {
  fs.mkdirSync(logsDir, { recursive: true });
}

// Morgan: HTTP request logging to file
// Essential for Manager to track production activities and delivery assignments
const accessLogStream = fs.createWriteStream(
  path.join(__dirname, "logs", "access.log"),
  { flags: "a" }, // Append mode
);

// Morgan format: Combined Apache-style logs for production tracking
app.use(morgan("combined", { stream: accessLogStream })); // Log to file
app.use(morgan("dev")); // Log to console (colored)

console.log(
  "✅ Morgan logging middleware enabled (Harsha - Manager Production Tracking)",
);

Log Format (Combined):

:remote-addr - :remote-user [:date[clf]] ":method :url HTTP/:http-version" :status :res[content-length] ":referrer" ":user-agent"

Sample Log Entry:

::1 - - [05/Feb/2026:10:30:45 +0530] "GET /api/products HTTP/1.1" 200 1523 "http://localhost:5173/" "Mozilla/5.0"

4. Body Parser (Harsha)

Definition:
Body Parser middleware parses incoming request bodies before handlers, making the data available under req.body. It handles JSON and URL-encoded form data.

Package: body-parser
Installation: npm install body-parser

Where Used:

  • Production milestone form submissions
  • Delivery assignment forms
  • Manager Dashboard data updates
  • All POST/PUT/PATCH requests

Code Implementation:

// =============================================================================
// HARSHA - Manager Dashboard Middleware (continued)
// =============================================================================

const bodyParser = require("body-parser");

// Body Parser: Parse production milestone and delivery assignment form data
app.use(bodyParser.json({ limit: "50mb" })); // Parse JSON bodies
app.use(bodyParser.urlencoded({ extended: true, limit: "50mb" })); // Parse URL-encoded bodies

console.log("✅ Body-parser middleware enabled (Harsha - Manager Forms)");

Configuration Options:

  • limit: "50mb" - Maximum request body size (for large design files)
  • extended: true - Allows nested objects in URL-encoded data

Usage Example:

// Accessing parsed body in route handler
app.post("/api/milestones", (req, res) => {
  const { orderId, status, notes } = req.body; // Body parsed by body-parser
  // Process milestone update
});

5. Compression (Kumar)

Definition:
Compression middleware compresses HTTP responses using gzip or deflate compression, reducing the size of data transferred over the network. This is critical for performance when serving large 3D models and design assets.

Package: compression
Installation: npm install compression

Where Used:

  • 3D Design Studio (Three.js model loading)
  • Designer Selection page (portfolio images)
  • Customization interface (texture files)
  • All API responses

Code Implementation:

// =============================================================================
// KUMAR - 3D Design Studio Performance Middleware
// Role: 3D Design Studio, Three.js Preview, Designer Selection, Customization
// =============================================================================

const compression = require("compression");

// Compression: Gzip compress 3D models, textures, and design assets
// Critical for 3D Design Studio performance with large model files
app.use(
  compression({
    level: 6, // Compression level (1-9) - balanced for 3D assets
    threshold: 1024, // Only compress responses > 1KB
    filter: (req, res) => {
      // Enable compression for 3D model routes and design assets
      if (req.headers["x-no-compression"]) return false;
      return compression.filter(req, res);
    },
  }),
);

console.log("✅ Compression middleware enabled (Kumar - 3D Design Studio)");

Configuration Options:

  • level: 6 - Compression level (1=fastest, 9=best compression)
  • threshold: 1024 - Minimum response size to compress (1KB)
  • filter - Custom function to determine which responses to compress

Performance Impact:

  • 3D models (.glb, .gltf): ~60-70% size reduction
  • Images: ~30-50% size reduction
  • JSON responses: ~70-80% size reduction

6. Multer (Manoj)

Definition:
Multer is a middleware for handling multipart/form-data, primarily used for uploading files. It provides control over file storage, naming, and validation.

Package: multer
Installation: npm install multer

Where Used:

  • Designer Dashboard (design uploads)
  • Portfolio management
  • Product image uploads
  • Send designs to Customer/Manager

Upload Directories:

  • /public/uploads/designs - Designer created designs
  • /public/uploads/portfolios - Designer portfolio images
  • /public/uploads/products - Product images

Code Implementation:

// =============================================================================
// MANOJ - Designer Dashboard File Upload Middleware
// Role: Designer Dashboard, Design Upload, Send to Customer/Manager
// =============================================================================

const multer = require("multer");
const path = require("path");
const fs = require("fs");

// Create upload directories using fs/promises for design files
// Essential for Designer Dashboard file management
const uploadDirs = [
  "public/uploads/designs", // Designer created designs
  "public/uploads/portfolios", // Designer portfolio images
  "public/uploads/products", // Product images
];

// Use fsPromises for async directory creation (Manoj - fs/promises)
uploadDirs.forEach((dir) => {
  const fullPath = path.join(__dirname, dir);
  if (!fs.existsSync(fullPath)) {
    fs.mkdirSync(fullPath, { recursive: true });
  }
});

// Multer Storage Configuration for Designer uploads
const storage = multer.diskStorage({
  destination: function (req, file, cb) {
    // Route designs to appropriate folders
    let folder = "public/uploads/designs"; // Default for designer uploads
    if (req.baseUrl.includes("portfolio") || req.path.includes("portfolio")) {
      folder = "public/uploads/portfolios"; // Designer portfolio
    } else if (
      req.baseUrl.includes("product") ||
      req.path.includes("product")
    ) {
      folder = "public/uploads/products";
    }
    cb(null, path.join(__dirname, folder));
  },
  filename: function (req, file, cb) {
    // Generate unique filename for designer uploads: timestamp-originalname
    const uniqueSuffix = Date.now() + "-" + Math.round(Math.random() * 1e9);
    const ext = path.extname(file.originalname);
    cb(null, uniqueSuffix + ext);
  },
});

// File Filter: Only allow design file types (images and PDFs)
// Validates files uploaded by designers
const fileFilter = (req, file, cb) => {
  const allowedTypes = [
    "image/jpeg",
    "image/jpg",
    "image/png",
    "image/gif",
    "application/pdf", // Design specifications
  ];
  if (allowedTypes.includes(file.mimetype)) {
    cb(null, true);
  } else {
    cb(
      new Error("Invalid file type. Only JPG, PNG, GIF and PDF allowed."),
      false,
    );
  }
};

// Multer Upload Instance for Designer Dashboard
const upload = multer({
  storage: storage,
  fileFilter: fileFilter,
  limits: {
    fileSize: 5 * 1024 * 1024, // 5MB max for design files
    files: 5, // Max 5 design files at once
  },
});

// Store upload middleware for Designer routes
app.set("upload", upload);

console.log(
  "✅ Multer file upload middleware configured (Manoj - Designer Uploads)",
);

Usage in Routes:

// Single file upload
app.post("/api/designs/upload", upload.single("design"), (req, res) => {
  const file = req.file; // Uploaded file info
  res.json({ success: true, filename: file.filename });
});

// Multiple files upload
app.post("/api/portfolio/upload", upload.array("images", 5), (req, res) => {
  const files = req.files; // Array of uploaded files
  res.json({ success: true, count: files.length });
});

7. fs/promises (Manoj)

Definition:
The fs/promises module provides promise-based file system operations, allowing for cleaner async/await syntax when working with files and directories.

Package: Built-in Node.js module
Installation: No installation required

Where Used:

  • Creating upload directories
  • Reading design files
  • File management operations
  • Designer portfolio handling

Code Implementation:

// =============================================================================
// MANOJ - File System Operations
// Role: Designer Dashboard, Design Upload, Send to Customer/Manager
// =============================================================================

const fsPromises = require("fs").promises;

// Example: Async directory creation
async function ensureDirectoryExists(dirPath) {
  try {
    await fsPromises.access(dirPath);
  } catch {
    await fsPromises.mkdir(dirPath, { recursive: true });
  }
}

// Example: Read design file
async function readDesignFile(filePath) {
  try {
    const data = await fsPromises.readFile(filePath);
    return data;
  } catch (error) {
    console.error("Error reading file:", error);
    throw error;
  }
}

// Example: Delete design file
async function deleteDesignFile(filePath) {
  try {
    await fsPromises.unlink(filePath);
    return true;
  } catch (error) {
    console.error("Error deleting file:", error);
    return false;
  }
}

Installation: npm install cookie-parser

const cookieParser = require("cookie-parser");

// Cookie Parser: Manage cart sessions and user preferences

9. CSRF Protection (Hari)

Definition:
Cross-Site Request Forgery (CSRF) protection prevents malicious websites from making unauthorized requests on behalf of authenticated users. Our implementation uses session-based tokens.

Package: Custom implementation using crypto
Installation: Built-in Node.js module

Where Used:

  • Checkout form submission
  • Cart modifications
  • Order placement
  • Payment processing
  • All state-changing POST/PUT/DELETE requests

Code Implementation:

// =============================================================================
// HARI - CSRF Protection Middleware
// Role: Home, Shop, Cart, Checkout, Order Tracking, OTP Verification
// =============================================================================

const crypto = require("crypto");

// Generate CSRF Token for checkout security
const generateCsrfToken = () => {
  return crypto.randomBytes(32).toString("hex");
};

// CSRF Protection Middleware - Protects Cart and Checkout from CSRF attacks
const csrfProtection = (req, res, next) => {
  // Skip CSRF for GET, HEAD, OPTIONS requests (safe methods)
  if (["GET", "HEAD", "OPTIONS"].includes(req.method)) {
    return next();
  }

  const token = req.headers["x-csrf-token"] || req.body._csrf;
  const sessionToken = req.session.csrfToken;

  if (!token || !sessionToken || token !== sessionToken) {
    return res.status(403).json({
      success: false,
      message: "Invalid CSRF token - Checkout security violation",
    });
  }
  next();
};

console.log(
  "✅ CSRF protection middleware configured (Hari - Checkout Security)",
);

CSRF Token Endpoint:

// Endpoint to get CSRF token
app.get("/api/csrf-token", (req, res) => {
  // Generate new token if not exists
  if (!req.session.csrfToken) {
    req.session.csrfToken = generateCsrfToken();
  }
  res.json({
    success: true,
    csrfToken: req.session.csrfToken,
  });
});

Frontend Usage:

// Fetch CSRF token before checkout
const response = await fetch("/api/csrf-token");
const { csrfToken } = await response.json();

// Include token in checkout request
await fetch("/api/checkout", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-CSRF-Token": csrfToken, // Include CSRF token
  },
  body: JSON.stringify(orderData),
});

Middleware Execution Order

The middleware executes in the following order:

1. Helmet (Security Headers)           → Chetan
2. Compression (Response Compression)  → Kumar
3. Morgan (HTTP Logging)               → Harsha
4. Body Parser (Request Parsing)       → Harsha
5. Cookie Parser (Cookie Handling)     → Hari
6. Session (Session Management)        → Built-in
7. CORS (Cross-Origin Requests)        → Built-in
8. CSRF Protection (Form Security)     → Hari
9. Rate Limiting (On specific routes)  → Chetan
10. Multer (On upload routes)          → Manoj
